Wrap markdown content in `<section>` tags automatically, grouped by header level, and hoisting or creating an anchor tag on the section; perfect for Intersection Observers, scroll-spying, or semantic styling without manual markup.

```md
# Introduction

Hello world.

## Details

More info here.
```

renders to:

```html
<section id="introduction" aria-labelledby="introduction-heading">
	<h1 id="introduction-heading">Introduction</h1>
	<p>Hello world.</p>
	<section id="details" aria-labelledby="details-heading">
		<h2 id="details-heading">Details</h2>
		<p>More info here.</p>
	</section>
</section>
```

## The problem

Modern web layouts often require grouping content into logical blocks—for example, to trigger animations as sections enter the viewport or to build sticky navigation that knows which part of the page you're reading.

Markdown is inherently flat. While you can manually wrap blocks in `<div>` or `<section>` tags, it breaks the readability of the raw text and is prone to errors. **markdown-it-anchor-sections bridges the gap** by treating your header hierarchy as the source of truth for your document's structure.

## Features

- **Hierarchical nesting** — lower-level headers (like `h3`) are automatically nested within higher-level sections (like `h2`)
- **Attribute-aware** — works seamlessly with `markdown-it-attrs` sections inherit the same IDs as their headers
- **Semantic HTML** — produces clean, valid `<section>` structures that reflect your content's outline
- **Zero configuration** — works out of the box with sensible defaults
- **Lightweight** — tiny footprint with no external dependencies

## Usage

```js
import md from "markdown-it";
import anchorSections from "@allons-y/markdown-it-anchor-sections";

const parser = md().use(anchorSections);

const src = `
# First header
lorem ipsum

## Second header
dolor sit amet
`;

console.log(parser.render(src));
```

### With attributes

If you use [markdown-it-attrs] before this plugin, the generated `<section>` tags will inherit the id applied to the headers and retain any other attributes on the header.

```js
import md from "markdown-it";
import attrs from "markdown-it-attrs";
import anchorSections from "@allons-y/markdown-it-anchor-sections";

const parser = md().use(attrs).use(anchorSections);
```

**Markdown:**

```md
# Great stuff {.jumbotron #intro}

lorem ipsum
```

**Output:**

```html
<section id="intro" aria-labelledby="intro-heading">
	<h1 class="jumbotron" id="intro-heading">Great stuff</h1>
	<p>lorem ipsum</p>
</section>
```

## Options

### `slugify`

Section ids come from the heading text: lowercased, words joined with dashes, & the rest percent-encoded, so every id works as a URL fragment & non-Latin headings keep one. Duplicate headings get `-1`, `-2` suffixes. Pass your own function to change that:

```js
const parser = md().use(anchorSections, {
	slugify: (text) => text.trim().toLowerCase().replace(/\s+/g, "_"),
});
```

An explicit id, like `{#intro}` from [markdown-it-attrs], always wins.

## Accessible names

Each section is named by its heading: the section gets `aria-labelledby`, & the heading gets the section's id plus `-heading` for it to point at (see the output above). Assistive technology then exposes every section as a `region` landmark, so a long document produces many landmarks. A heading with an explicit id (`{#intro}`) keeps that id on the section.

## How it works

1. Iterates through the token stream generated by `markdown-it`.
2. When a header token is encountered, it identifies its level (1–6).
3. Closes any open sections of the same or lower level.
4. Opens a new `<section>` tag.
5. If the header has attributes (classes, IDs, etc.), they are copied to the opening `<section>` tag.
6. Automatically closes all remaining tags at the end of the document.

## Styling the active section

Each section carries the id, so a table-of-contents link like `<a href="#details">` points at the whole section, not just its heading. That is what lets you style the link for the section currently in view.

### CSS only

`scroll-target-group` marks the TOC as a group of scroll markers, & `:target-current` matches the link whose target is in view. No JavaScript:

```css
nav ol {
	scroll-target-group: auto;
}

nav a:is(:target-current, [aria-current="location"]) {
	text-decoration: underline;
	text-decoration-thickness: 0.2em;
}
```

`:target-current` is experimental & only ships in Chromium (135+) at the time of writing; check [MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/:target-current) for current support. The `:is()` wrapper matters: it ignores a selector the browser doesn't understand, so the rule still applies to `[aria-current="location"]` elsewhere.

### Fallback for other browsers

Set `aria-current` with an `IntersectionObserver` where `:target-current` isn't available. The observed band sits near the top of the viewport, & the last section inside it wins, so a nested section takes over from its parent:

```js
if (!CSS.supports("selector(:target-current)")) {
	const links = new Map(
		[...document.querySelectorAll("nav a[href^='#']")].map((a) => [a.hash.slice(1), a]),
	);
	const sections = [...links.keys()].map((id) => document.getElementById(id));
	const visible = new Set();

	const observer = new IntersectionObserver(
		(entries) => {
			for (const { target, isIntersecting } of entries) {
				if (isIntersecting) visible.add(target);
				else visible.delete(target);
			}
			const active = sections.filter((section) => visible.has(section)).at(-1);
			for (const [id, link] of links) {
				if (id === active?.id) link.setAttribute("aria-current", "location");
				else link.removeAttribute("aria-current");
			}
		},
		{ rootMargin: "-20% 0px -75% 0px" },
	);

	for (const section of sections) observer.observe(section);
}
```

The page can't scroll a last section that is shorter than the viewport up to the band, so give it room, e.g. `section:last-of-type { min-height: 100vh; }`. The native `:target-current` doesn't need this.

### Accessibility notes

- **Sections are named regions.** A `<section>` becomes a `region` landmark when it has an accessible name ([HTML-AAM](https://www.w3.org/TR/html-aam-1.0/#el-section)), & this plugin names each one with `aria-labelledby`. A long document therefore has many landmarks.
- **Name the TOC.** Use `<nav aria-label="On this page">` so it is distinguishable from other navigation.
- **Don't rely on color or weight alone.** The active style above uses an underline: it survives forced-colors mode & doesn't change the link's width, so the TOC doesn't reflow as you scroll.
- **`aria-current="location"`** is the right token for the current place in a page ([WAI-ARIA](https://www.w3.org/TR/wai-aria-1.2/#aria-current)). Don't also add a live region: announcing every scroll change is noise.
- **Use `scroll-target-group`, not `scroll-marker-group`, for a TOC.** The latter gives the links `tablist` / `tab` semantics, which don't fit page navigation.
- **The id lives on the section.** The heading gets `<id>-heading` instead. Put `scroll-margin-top` on `section[id]` so a fixed header doesn't cover the heading after a link is followed. Anything that expected `h2#id` needs updating.
- **Smooth scrolling:** guard it with `@media (prefers-reduced-motion: no-preference)`.
